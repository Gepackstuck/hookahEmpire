## Решения, зафиксированные для v0.1

- Движок: Godot 4.7.2.
- Платформа разработки: macOS.
- Presentation target: преимущественно 2D isometric.
- MVP-локация: только гараж.
- Primary USP: player-created recipes + hands-on preparation.
- Два режима приготовления: quick и manual.
- Recipe book хранит player-created mixes.
- Guest satisfaction зависит от recipe, guest, trend и execution.
- Heat/charcoal — лёгкая service-management механика.
- Re-preparation поддерживается.
- Furniture placement — grid-based.
- Dialogue — data-driven.
- Save data — versioned.
- MVP заканчивается на invitation to serve outside guests.

### Зафиксировано в M0

- Рендерер: Compatibility (`gl_compatibility`), 3D-настройки Jolt/d3d12 удалены.
- Базовое разрешение: 1920×1080, stretch `canvas_items`, aspect `expand`.
- Формат контента: JSON в `data/`.
- Корневая `ui/` — общие UI-ресурсы (темы); экраны — в `scenes/ui/` и `scripts/ui/`.
- Autoloads: только `GameState` и `SaveService`. `GameState` хранит данные и сигналы без логики.
- Логирование: `GameLog.debug/info/warn/error(tag, message)`.
- Тесты: собственный раннер `tests/run_tests.gd`, без внешних фреймворков.
- Имя агента в документах: Беброид.
- Коммиты делает разработчик, агент их не создаёт.

- Вид: изометрия в духе Restaurant City (ориентир, не копия): ромбовидный пол, две задние стены, камера следует за игроком (zoom 2, лимиты по границам комнаты).
- Размер гаража: 20×15 клеток; клетка 64×32 px.
- Управление: свободное перемещение (WASD/стрелки), скорость одинакова во всех 8 направлениях; взаимодействие — E.
- Логика в координатах сетки; NPC (кальянщик) позже используют `GarageGrid.find_path()`.
- Временный арт: эмодзи (игрок 🕺, при курении 😶‍🌫️, дверь 🚪, ящик 📦, лампа 💡), стол рисуется кодом, кальян — фото-заглушка `art/furniture/hookah_test.png`.
- Подсказка взаимодействия — клавиша «E» в рамке над объектом.

### Зафиксировано в M3

- 11 ингредиентов: 🍓 клубника, 🍉 арбуз, 🍇 виноград, 🍑 персик, 🥭 манго, 🫐 черника, 🍎 яблоко, 🍋 лимон, 🍈 лайм, 🍦 ваниль, 🥤 кола. Мята убрана (её роль — «Ледяная нотка»). Все доступны с начала (покупки — позже). Данные: `data/ingredients/`.
- «Ледяная нотка» ❄️ — модификатор-галочка (`ice`), а не ингредиент; меняет вкусовой профиль и id рецепта.
- Порции задаются кнопками − / + (вместо ползунков), есть «Сбросить». Общий бюджет — 4 порции (`max_portions` в `scoring.json`): 1 ингредиент — до 4 порций, 2 — 1+3 или 2+2, 3 — 1+2+1 или 1+1+1, 4 — 1+1+1+1; «+» блокируется, когда бюджет исчерпан; допускается 1 ингредиент (нужен для секретного рецепта).
- Доли приводятся к 20 целым единицам (метод наибольших остатков); эквивалентные миксы (2:1:1 = 4:2:2) — один рецепт; id рецепта = `r_` + md5 канонического ключа.
- Качество = 0.70·Synergy + 0.30·Balance (+ бонус секретного). Синергия — 20 пар (`docs/RECIPE_RESEARCH.md`; часть без источника, это tuning), неизвестные пары нейтральны: значение 0 → 58 баллов (`synergy_neutral`), 1 → 100. Идеальный рецепт вне секретных: 🍓 клубника + 🍦 ваниль («Великолепно»; лёд его ухудшает). Слова качества: Плохо/Слабо/Нормально/Хорошо/Отлично/Великолепно. В M3 в смесителе только слова и полоски вкуса; числа — в книге рецептов.
- Автоимя: «Клубника + Мята», «… +N», «Соло: X», « ❄️»; можно переименовать (пустое имя = автоимя).
- Смеситель сбрасывается при закрытии, если в нём сохранили рецепт (без сохранения черновик остаётся); книга рецептов при каждом открытии начинается без выбранного рецепта.
- Стол смешивания украшен векторными предметами (`visual.props`: hookah/jar/cup/coals); сияние 📜 усилено.
- Название секретного рецепта: «Двойное яблочко 🍎🍎».
- Секретный рецепт «Двойное яблочко»: только 4 порции яблока (весь бюджет); 1–3 порции — обычный рецепт «Соло: Яблоко» (другой id, key с `#partial`). Модификаторы игнорируются (бонус +20); секретные рецепты переименовывать нельзя.
- Повторное сохранение существующего рецепта ничего не меняет. `times_used` растёт только через `RecipeSystem.record_result` (приготовление для гостя, M4+); у нового рецепта 0.
- Смешивание — E у стола (стол 4×2, зона «Смешать»); книга рецептов — кнопка в смесителе и объект 📜 на столе (временное место) с сиянием при приближении; между зонами стола и книги гистерезис фокуса (0.25 клетки).
- Эмодзи игрока и друзей зеркалятся в сторону движения. Константа `Player.SPRITE_FACES_RIGHT` и поле гостя `sprite_faces` задают, куда смотрит исходный эмодзи.
- Рецепты живут в `GameState.recipes` (save_version остаётся 1; запись на диск — M11).

### Чек-лист верификации M3 (ручной)

1. У стола подсказка «Смешать», у 📜 — «Открыть книгу рецептов», без мерцания между ними; у книги сияние.
2. E у стола открывает смеситель; Esc закрывает; ходьба заблокирована.
3. Кнопки − / +: на 4 активных ингредиентах остальные «+» блокируются; галочка ❄️ добавляет эмодзи в подпись и состав; невыбранные ингредиенты затемняются целиком (название, эмодзи, кнопки), когда «+» для них заблокирован — слоты заняты или порции закончились; проценты, полоски, слово качества обновляются.
4. Сохранение создаёт рецепт; то же соотношение (2:1 и 4:2) не создаёт дубликат, растёт счётчик использований.
5. Яблоко ×4 → сообщение о секретном рецепте «Двойное яблочко».
6. Переименование в смесителе и в книге; пустое имя возвращает автоимя.
7. Книга: фильтр по ингредиенту, сортировка, детали, «Загрузить в смеситель»; у секретного рецепта нет переименования.
8. Эмодзи игрока и Дениса поворачиваются по направлению ходьбы (если наоборот — поправить константу/`sprite_faces`).
